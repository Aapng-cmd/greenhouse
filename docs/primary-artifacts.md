# ПЕРВИЧНЫЕ АРТЕФАКТЫ. ВЫЧИСЛИТЕЛЬНЫЙ КОНТУР ТЕПЛИЦЫ

Вариант 22

Окружение функции «обработать заявку на расчёт контура теплицы»: документы, данные, продукты, исполнители, программы, цели и показатели. Проектные схемы того же контура - сиквенс, классы, поток с дорожками и ArchiMate.

## 1. Функция верхнего уровня

Обработать съём датчика: принять заявку в очередь расчёта, при переполнении выбить последнюю поступившую, выбрать одну заявку по приоритету контура, посчитать её на воркере группы, отдать команду актуатору и учесть результат.

## 2. Документы

| Артефакт | Кто создаёт | Зачем |
|---|---|---|
| Показание датчика | Источник И1..И4 | Вход функции: температура, влажность, свет или уровень вредителей |
| Журнал очереди расчёта | Диспетчер постановки / буфер | Фиксирует постановку в хвост (Д1ОЗ2) и выбивание последней заявки (Д1ОО4) |
| Команда актуатору | Воркер после complete() | Нагрев, охлаждение, полив, вентиляция, UV-лампы, зонты, химикаты |
| Календарь событий | Пошаговый режим ОД1 | Состояние системы на каждом шаге: событие, БП, приборы, указатель |
| Сводная таблица прогона | Авторежим ОР1 | p отказа, времена, загрузка приборов |
| auto.log | Авторежим | Календарь каждого подбора N |

## 3. Данные

| Артефакт | Содержание |
|---|---|
| Очередь заявок | Идентификаторы заявок в общей БП, порядок поступления |
| Состояние воркеров | idle или id заявки на P1..P8 |
| Указатель Д2П2 | Следующий воркер внутри группы показателя |
| Климат теплицы | Текущие T, влажность, свет, вредители, облачность |
| Оптимум роста | Целевые значения, к которым двигают актуаторы |
| Статистика контуров | Сгенерировано, отказано, обслужено, времена ожидания и обслуживания |

## 4. Продукты функции

| Продукт | Результат для хозяйства |
|---|---|
| Управляющее воздействие | Климат сдвигается к оптимуму выбранного контура |
| Отказ съёма | Команда не выдана; контур остаётся на прежнем значении |
| Отчёт эффективности | Можно сравнить ёмкость БП, число воркеров и интенсивности |

## 5. Оргединицы и роли

| Роль | В модели |
|---|---|
| Датчиковый контур | Источники И1..И4 |
| Служба приёма расчётов | Диспетчер постановки |
| Служба назначения расчётов | Диспетчер выбора |
| Вычислительный узел теплицы | Воркеры P1..P8 по группам |
| Агроном / оператор | Читает ОР1 и окно теплицы; не стоит в очереди СМО |

## 6. Программные продукты

| Продукт | Роль |
|---|---|
| `smo.py` | Имитационная модель: decode / step / auto |
| `dispatcher-put` | Постановка в БП |
| `buffer` | Очередь Д1ОЗ2 / Д1ОО4 |
| `dispatcher-select` | Д2Б4 и Д2П2 |
| `worker-*` | Обслуживание ПЗ1 |
| `event-calendar` | Модельное время |
| `stats` | Таблицы ОР1 |
| `greenhouse-sim` | Qt: среда и кадры JSON, не буфер. `greenhouse_view` рисует дом, `pipeline_view` - схему |

## 7. Цели и KPI

| Цель | Показатель | Ориентир |
|---|---|---|
| Не терять расчёты | Доля отказов p | не выше 0.10 |
| Не простаивать воркеры | Загрузка прибора Kисп | около 0.90 |
| Быстрый цикл «съём - команда» | Среднее время заявки в системе Tпреб | минимальное среди допустимых |
| Держать климат у оптимума | Отклонение T, влажности, света, вредителей | после обслуживания уменьшается |
